# Datasets

> Dataset inventory last verified: 2026-07-25.

This directory holds the fixture files the `datex4j-integration-tests` round-trip suite parses,
validates, re-serializes and diffs (see the module's own README for how the harness runs). It also
holds, per country, a `README.md` describing how to obtain that country's real AFIR dataset even
where the file itself is not committed here.

Fixture README files are authoritative for immutable snapshot provenance and expected test
behavior. Current National Access Point status and access policy belong in `docs/afir/nap/`; the
cross-domain comparison belongs in `docs/datex-test-data-sources.md`.

> For a catalogue of open DATEX II data sources across **all** domains (situations, SRTI, parking,
> VMS, roadworks, EV charging) — not only AFIR — see
> [`docs/datex-test-data-sources.md`](../../../../../docs/datex-test-data-sources.md).

Fixtures come in two on-the-wire formats, dispatched by the harness on the `Dataset.Format` recorded
in the catalog:

- **XML** — validated against the official DATEX II XSDs and round-tripped through `datex4j-xml`
  (the seven mandatory checks).
- **JSON** — conformant DATEX II JSON rooted at a `MessageContainer` (the shape real National Access
  Points such as Fintraffic publish), round-tripped through `datex4j-json` for idempotency and
  content fidelity. Used by the committed **Finland** real-world dataset.

## Layout

- [`synthetic/afir-recharging/`](./synthetic/afir-recharging) — a hand-authored, XSD-valid AFIR
  recharging fixture, generated by the project itself (`SyntheticDatasets.java`). Always committed;
  guarantees the suite is green offline with no external dependency.
- `official/examples/` — reserved for an official DATEX II example payload, if and when one with a
  confirmed, redistributable license is found (see
  [the official resources review](../../../../../docs/afir/official-datex-resources.md#official-examples)
  for the search done so far). This directory remains empty until an official example with clear
  redistribution rights is identified.
- [`finland/`](./finland) — **a committed real-world dataset**: `afir-messagecontainer.v3_6.json`,
  a trimmed excerpt of Fintraffic's live AFIR feed (CC BY 4.0, conformant DATEX II JSON v3.6). Its
  `README.md` is the filled-in metadata record; the same real values are the `datex4j-json` codec's
  Fintraffic oracle.
- `germany/`, `france/`, `netherlands/`, `denmark/`, `belgium/`, `austria/`, `sweden/` —
  one directory per remaining country covered by [`docs/afir/nap/`](../../../../../docs/afir/nap).
  Each holds a `README.md` with download instructions for that country's public AFIR/DATEX II
  dataset(s) and, once a file's license is confirmed suitable, the dataset file(s) themselves
  alongside their own metadata `README.md`.

## Policy: what gets committed

Document real-world datasets before downloading them, then confirm every condition below before
committing them:

1. **The license is confirmed and permits redistribution.** A dataset published under an explicit
   open license (e.g. Creative Commons, a national "license ouverte", or a license the publisher
   confirms in writing) may be committed. A dataset whose license is unstated, restrictive, or that
   requires an authenticated/paid download is **documented, not committed** — the country's
   `README.md` explains how to fetch it yourself.
2. **The file is small enough for a git repository.** Even under a permissive license, large NAP
   exports (full national snapshots) are not committed; the `README.md` documents the source and, if
   useful, a way to fetch a bounded excerpt.
3. **The file is registered.** A committed dataset is useless to the suite until it is wired into
   [`DatasetCatalog.all()`](../../java/dev/juherr/datex4j/it/support/DatasetCatalog.java) (see
   "Contributing a new dataset" below) and accompanied by its own metadata `README.md` in the same
   directory (see the template below, and
   [`synthetic/afir-recharging/README.md`](./synthetic/afir-recharging/README.md) for a filled-in
   example).

Where no dataset currently meets these conditions for a country, that country's `README.md` says so
plainly instead of committing something that shouldn't be there.

## Metadata template

Every dataset directory (synthetic or real) documents its file(s) with a short `README.md` using
this template:

```markdown
# Dataset: <country or "synthetic"> / <short name>

- **Source URL:** <where the file was obtained, or "n/a" for synthetic fixtures>
- **License:** <the exact license, e.g. "Creative Commons 4.0 BY", "License Ouverte 1.0", "Apache-2.0">
- **Download date:** <YYYY-MM-DD the file was fetched, or "n/a" for synthetic fixtures>
- **DATEX version:** <e.g. 3.6, 3.7>
- **Profile:** <e.g. "AFIR recharging (EnergyInfrastructureTablePublication)">
- **Country:** <the country this dataset represents>
- **Expected object counts:** <e.g. "1 EnergyInfrastructureTable, 3 EnergyInfrastructureSite">
- **Remarks:** <anything a future maintainer should know before touching this file>
- **Known quirks:** <schema-version drift, non-standard extensions, validation warnings — or "none">
```

## Contributing a new dataset

1. Confirm the dataset's license explicitly permits redistribution, and that the file is reasonably
   small (see "Policy" above). If either is unclear, add or update the country's `README.md` with the
   download instructions instead of committing the file.
2. Add the resource file under the relevant country directory (create the directory if it does not
   exist yet).
3. Add a `README.md` next to it, filled in from the metadata template above.
4. Register the dataset in
   [`DatasetCatalog.all()`](../../java/dev/juherr/datex4j/it/support/DatasetCatalog.java) — a
   `Dataset` record with an id, the country/category, the classpath-relative resource path, and the
   expected root publication class — so the round-trip suite picks it up automatically.
5. Run the `datex4j-integration-tests` module and confirm the new dataset round-trips cleanly.
